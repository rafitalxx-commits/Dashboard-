# Descuentos sucesivos en facturas de proveedor (LAB)

El editor conserva por línea tres porcentajes explícitos: `DTO` comercial, `DTO extra` y `Pronto pago`. Se aplican en ese orden, multiplicando factores; no se suman. Por ejemplo, 45%, 5% y 2% producen un descuento efectivo del 48,795%. La función pura compartida `shared/supplierInvoiceDiscounts.ts` calcula ese porcentaje y la base neta, sin IA ni inferencias del PDF.

El operador puede introducir los dos descuentos adicionales en bloque (sobre todas las líneas gravadas) o corregirlos por línea. La base de cada línea se redondea a céntimos y su cuota de IVA se recalcula con la tasa seleccionada. Los importes declarados del PDF permanecen separados para cotejo; el editor no los sobrescribe automáticamente. Si hay una diferencia, se revisan cantidades, precios unitarios —hasta cinco decimales— y descuentos. El total de impuesto sigue permitiendo un ajuste manual de céntimos, con cuotas y base verificadas antes del guardado.

El registro local guarda los tres porcentajes. Para el borrador de Odoo, el puente transmite en cada línea el descuento efectivo equivalente. Cuando existen descuentos sucesivos, la puerta del borrador exige que la suma calculada de líneas coincida con la base declarada dentro de un céntimo; no usa la tolerancia de precios históricos de tres decimales. El «Ajuste Web (sin IVA)» no representa descuentos comerciales ni de pronto pago sujetos a IVA. Puede coexistir con ellos únicamente como resto no gravado documentado: el editor muestra `base declarada − bases de productos`, exige que las cuotas de IVA de los productos coincidan con el PDF y crea una sola línea de ajuste sin impuesto. El operario debe cotejarla y guardarla localmente antes de preparar el borrador. El producto AJUSTEWEB se resuelve en Odoo por su referencia interna exacta y tipo; si no existe de forma única y activa, el borrador se bloquea.

La creación de un borrador real y cualquier promoción a producción requieren sus validaciones y autorizaciones separadas. La prueba de esta regla usa números sintéticos y un store temporal; no escribe Odoo ni Drive.
